# 0014. Project knowledge graph via Basic Memory (markdown-native)
Date: 2026-07-07
Status: accepted
Context: The owner asked for a knowledge graph of the project that future developers — human AND AI — can use and extend. Constraints from our environment: ephemeral dev containers (anything not in git is lost), no external services, sessions may run without any particular tool installed, and humans review everything on GitHub. Candidates evaluated: Basic Memory (markdown files with wiki-link relations + MCP server, AGPL-3.0, actively maintained, v0.22.1), the MCP reference memory server (MIT, JSONL entity/relation store), Graphiti and Cognee (temporal/LLM graph stores; need Neo4j-class services and LLM calls), Kuzu (embedded graph DB; binary artifact in git, custom tooling required).
Decision: Use Basic Memory with the store committed at `docs/knowledge/`. The Markdown files ARE the graph (frontmatter type/tags, `- [category] fact` observations, `- verb [[Target]]` relations), so the knowledge is fully usable with zero tooling; the tool adds search, graph traversal, and MCP access for AI sessions. `scripts/bm` is the only entry point: it self-bootstraps (uv tool install, project registration) and fixes two environment quirks — the agent proxy intercepting the tool's localhost API (NO_PROXY) and the semantic-search embedding model being undownloadable under the network policy (FTS5 full-text only). `.mcp.json` exposes the same store to Claude Code sessions as MCP tools. Conventions and update rules live in `docs/knowledge/README.md`.
Consequences: Humans browse/edit plain Markdown on GitHub; AI sessions query/write through MCP or CLI; the graph survives tool death because files are the source of truth. AGPL-3.0 is acceptable: Basic Memory is a local development tool, not a dependency of the shipped product (the backend license gate is unaffected). Costs: the tool normalizes frontmatter on sync (small diff churn, committed), plain-file edits need `scripts/bm sync` to reach the search index, and each fresh container pays one `uv tool install` (~seconds, PyPI is reachable).
Alternatives considered: MCP reference memory server (MIT, simplest, but the JSONL blob fails the "humans read it" requirement and encodes no conventions); Graphiti/Cognee (server + LLM dependencies incompatible with ephemeral offline-ish containers); Kuzu (binary DB in git, no human diffing); homegrown markdown graph (reinvents exactly what Basic Memory already maintains).
